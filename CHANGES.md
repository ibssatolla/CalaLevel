# Phase 3.3.3: password reset fix

- The reset link now opens the new-password screen. The app marks a reset as pending when the email is sent, and treats the returning link (`?code=`) as password recovery before any screen is chosen (`captureAuthReturn` in `js/auth/gate.js`).
- A failed or rate-limited request no longer breaks the link already sent. The browser's PKCE code verifier is put back when `resetPasswordForEmail` or `signUp` fails (`js/auth/auth.js`).
- Links that fail (expired, used, opened in another browser, `?error=` in the address) show a clear message on the forgot screen or Welcome. The error is removed from the address.
- Send limits on the forgot screen, kept on the device: 60 s between emails, 5 per hour, 3 min wait after a server rate limit. The button counts down and reads "Send a new link" after a send.
- Only the newest email works. The screen says so.
- Tests: 9 new checks in `flows8` (60 total). `flows7` 59, `flows9` 48, `real-config` 14, `sql-tests` 33, `unit3` 82, `flows2` 145, `flows3` to `flows6` all green.
- Not tested on the live project. The built-in Supabase mailer still has a low hourly limit; custom SMTP is the real fix for 429.
